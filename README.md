# AgentEval — Hermes · OpenClaw

Hermes와 OpenClaw의 답변 정확도, 응답 시간, 토큰 사용량, 도구 사용 과정과 장기 기억을 비교하는 평가 도구입니다. 평가 문항·정답·근거, 오류를 심은 검토용 문서, 채점 템플릿과 MLflow 집계 스크립트를 제공합니다.

## 평가 결과

[2026-10-12 평가 보고서](docs/evaluation-2026-10-12.md)에서 **Hermes는 답변 정확도와 사실·수정 기억 회수, OpenClaw는 전체 응답 속도와 시험한 내용의 장기 저장 방지에서 더 좋은 결과를 보였습니다.** 정확도 차이는 **0.79%p, 126개 채점 항목에서 1점**입니다. 현재 구성의 1회 평가이므로 보편적인 성능 우열을 뜻하지 않습니다.

| 지표 | OpenClaw | Hermes |
|---|---:|---:|
| 답변 정확도 · 부분점수 포함 | 98.02% · 123.5 / 126 | 98.81% · 124.5 / 126 |
| 중앙 응답 시간 · 동일 응답 113쌍 | 18.48초 | 22.20초 |
| P90 응답 시간 · 동일 응답 113쌍 | 54.51초 | 70.56초 |
| 입력 토큰 합계 · 동일 응답 113쌍 | 10,942,536 | 11,876,060 |
| 사실·수정 기억 회수 | 3 / 4 | 4 / 4 |
| 선호 적용 · 부분점수 포함 | 2 / 2 | 1.5 / 2 |
| 잡음의 장기 저장 방지 | 2 / 2 | 0 / 2 |
| 더미 비밀값의 장기 저장 방지 | 2 / 2 | 0 / 2 |
| 도구 금지 문항 준수 | 3 / 3 | 2 / 3 |

### 결과 해석

- **답변 품질:** A–D 문서 질의와 H 검색은 양쪽 모두 만점이고, E 오류 탐지도 14 / 15로 같았습니다. 차이는 F MCP 활용(OpenClaw 11.5 / 12, Hermes 12 / 12)과 G 기억 회수·선호 적용(5 / 6, 5.5 / 6)에서 나왔습니다. OpenClaw는 F01의 인증서 조건 표현과 G02의 기억 회수, Hermes는 G06의 코드 본문 미제시에서 감점됐습니다.
- **효율:** 전체 동일 응답쌍에서 OpenClaw의 중앙 응답 시간은 16.8% 짧고 입력 토큰은 7.9% 적었습니다(Hermes 분모). 기억 회수와 검색의 중앙 시간은 Hermes가 더 짧았지만, 검색 P90은 Hermes가 더 길었습니다. 시간은 native trace 기준이며 입력 토큰에는 캐시 읽기·쓰기가 포함되어 토큰 감소율을 비용 절감률로 해석할 수 없습니다.
- **기억:** Hermes는 사실·수정 기억 회수 4건을 모두 충족했지만 시험한 잡음과 더미 비밀값을 장기 기억에 남겼습니다. OpenClaw는 해당 네 사례의 저장을 피했지만, 회수 실패와 저장소 간 옛 값 잔존이 관측됐습니다. 저장 감사는 읽을 수 있는 장기 기억·기억 전용 색인과 60초 지연 스냅샷을 대상으로 했고 원시 대화 로그는 제외했습니다. 각 저장 방지 결과는 시험한 2건에 한정합니다.
- **도구 과정:** 학습을 포함한 에이전트별 126회 실행에서 도구 호출은 OpenClaw 963회, Hermes 507회였습니다. 설명·래퍼 호출을 포함하고 도구 구성도 달라 호출 수만으로 도구 선택의 적절성을 판단할 수 없습니다. Hermes는 E2에서 도구 사용 금지를 위반했고, OpenClaw는 검색 공급자 오류 이후 다른 경로로 답변을 완성했습니다. 오류 관측 기준이 달라 오류율 순위는 제시하지 않았습니다.

### 평가 범위와 한계

A–H **130문항** 중 저장 감사 4문항은 답변 정확도와 분리해 **126개 항목**을 채점했습니다. 주 비교는 학습 단계와 묶음 답변을 포함한 두 에이전트 합계 **252회 호출**입니다. 초기 기억·색인·이력 초기화가 불완전했던 36회 호출은 대조 기록으로 보존하고 주 비교에서 제외했습니다. 시간·토큰 비교는 양쪽에서 동일 답변의 계측이 가능한 **113쌍**으로 한정했습니다.

Claude는 블라인드 답변 채점, Codex는 실행·계측·기준 조정 감사, Antigravity는 출처 및 저장 내용 검토를 맡았습니다. 세 검토자의 독립 전수 투표 결과는 아닙니다. 제공 경로·도구 구성 차이와 채점 경계 사례가 남아 있으며, 신뢰구간과 계획·도구 선택·인자 정확성의 독립 정량 점수는 산출하지 않았습니다. 경계 사례의 대안 점수와 출처 감사 범위는 [상세 보고서](docs/evaluation-2026-10-12.md)에서 확인할 수 있습니다.

다음 평가에서는 Hermes의 저장 필터링·도구 금지 준수, OpenClaw의 기억 회수·갱신 일관성을 우선 확인하고, 경계 문항 기준을 정리한 뒤 반복 실행으로 결과 변동을 검증합니다.

## 설치와 준비

Python 3.12에서 다음 명령을 실행합니다.

```sh
python3 -m venv .venv-eval
.venv-eval/bin/pip install -r requirements-eval.txt
cp config.example.json config.local.json
.venv-eval/bin/python scripts/extended_runner.py --help
```

`config.local.json`의 `tracking_uri`와 `vault_name`을 환경에 맞게 지정합니다. `MLFLOW_TRACKING_URI`와 `EVAL_VAULT_NAME` 환경 변수가 로컬 설정보다 우선합니다. 기본 MLflow 주소는 `http://localhost:5000`입니다. 로컬 설정과 자격 증명은 Git에서 제외합니다.

실제 평가에는 Docker 기반 OpenClaw CLI, 별도로 준비한 Hermes 실행기(`hermes-docker/run-hermes.sh` 또는 `--hermes-container`), 문서 보관함 및 문항에 맞는 MCP 도구가 필요합니다. 배포 환경에 맞는 권한·기억 초기화 절차와 콜백도 별도로 준비해야 합니다.

## 데이터셋 준비와 실행

공개 문항에서 통합 CSV·JSON과 해시를 다시 생성합니다.

```sh
.venv-eval/bin/python scripts/prepare_extended_dataset.py
```

런타임과 MLflow를 준비한 후 문항 하나부터 실행합니다. `--experiment-id`에는 자신의 MLflow Experiment ID를 넣습니다.

```sh
.venv-eval/bin/python scripts/extended_runner.py \
  --dataset datasets/extended-20261012/questions.csv \
  --ids A01 --agents openclaw,hermes --reps 1 \
  --outdir runs/my-eval --memory off --experiment-id YOUR_EXPERIMENT_ID
```

`--all`은 전체 문항을 선택합니다. G의 기억 평가는 `--memory on`과 `--step-callback`을 포함한 별도 준비가 필요합니다. 도구 환경과 출처 보관함이 준비되지 않은 상태에서 전체 평가를 실행하지 마세요. 세부 옵션은 각 스크립트의 `--help`를 확인합니다.

외부 CLI의 LangChain trace와 내부 모델·도구의 native trace는 구분합니다. 실행 결과와 원본 응답은 `runs/`에 저장되며 Git에서 제외됩니다. trace 통합 스크립트는 기존 평가 이력용이므로 자신의 Experiment ID와 백업·출력 경로를 검토한 뒤 사용해야 합니다.

## 공개 데이터와 재현 범위

공개본의 도메인·계정·호스트·서비스 및 프로젝트 식별자는 가상 값으로 치환했습니다. `example.invalid` 주소는 접속용이 아닙니다. 합성 기억 평가의 더미 비밀값도 `MASKED_DUMMY_API_KEY`, `MASKED_DUMMY_DB_PASSWORD`로 바꾸고 질문·정답·검사 마커에 동일하게 반영했습니다.

보고서 수치는 마스킹 전 원래 평가 결과입니다. 공개 데이터셋은 별도 버전의 입력이며 원래 실행 증거와 해시가 다릅니다. 이전 `runs/`의 기억 스냅샷을 공개 프로토콜의 변경된 마커로 감사하면 원래 결과를 재현할 수 없습니다. 일부 출처 원문, 실제 Grafana 상태, 런타임·콜백과 원본 응답은 포함하지 않으므로 저장소만으로 원래 평가 전체를 재현할 수 없습니다.

마스킹 전 원본은 로컬 `.private-backup/`에 보존했습니다. 원본·실행 로그·자격 증명·가상환경·생성된 지식 그래프·배포 전용 유지보수 도구는 계속 Git에서 제외합니다.
