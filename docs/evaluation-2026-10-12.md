# Hermes · OpenClaw 비교 평가

> [!abstract] 한눈에 보는 결과
> **Hermes는 답변 정확도와 수정 기억 회수, OpenClaw는 전체 응답 속도와 기억 저장 필터링에서 앞섰다.**
> 정확도 차이는 **0.79%p**, 126개 채점 항목에서 **1점**이다. 현재 구성의 1회 결과이므로 보편적인 우열로 해석하지 않는다.

## Executive Summary

- **정확도는 작은 차이였다.** OpenClaw **98.02%**, Hermes **98.81%**. 기본 문서 질의와 검색은 동률이며, MCP·기억 문항에서 차이가 생겼다.
- **전체 효율은 OpenClaw가 좋았다.** 동일 응답 113쌍에서 중앙 응답 시간은 **16.8% 짧고**, 입력 토큰은 **7.9% 적었다**.
- **기억은 회수와 저장 판단을 나눠 봐야 한다.** Hermes는 사실·수정 기억 회수에서 앞섰다. OpenClaw는 시험한 잡음과 더미 비밀값의 장기 저장을 피했다.

---

## 1. 정확도 차이는 MCP·기억 문항에서 나왔다

**Hermes가 전체 영역에서 우세한 것은 아니다.** 두 에이전트는 기존 A–D와 검색 H에서 모두 만점을 받았다. 아래 점수는 부분점수 0.5를 포함한다.

| 평가 영역 | OpenClaw | Hermes |
| :--- | ---: | ---: |
| A–D · 문서 기반 답변 | 85 / 85 | 85 / 85 |
| E · 오류 탐지 | 14 / 15 | 14 / 15 |
| F · MCP 활용 | 11.5 / 12 | 12 / 12 |
| G · 기억 회수·선호 적용 | 5 / 6 | 5.5 / 6 |
| H · 논문·뉴스 검색 | 8 / 8 | 8 / 8 |
| **합계** | **123.5 / 126** | **124.5 / 126** |

차이를 만든 핵심 사례는 세 가지다. OpenClaw는 F01의 인증서 조건 표현에서 부분점수를 받았고, G02에서는 학습한 값을 회수하지 못했다고 답했다. Hermes는 G06에서 생성 코드 본문을 답변에 제시하지 않아 부분점수를 받았다.

> [!note]- 경계 사례와 채점 해석
> F01을 관대하게 채점하면 OpenClaw는 98.41%다. G06의 실제 생성 파일까지 인정하면 Hermes는 99.21%다. 주 점수는 사전 답변 기준을 유지했으며, 대안 점수는 별도 민감도 분석으로 기록했다.
> 오류 탐지의 모호한 E04를 제외하면 OpenClaw 98.80%, Hermes 99.60%다. 관측된 환각은 양쪽 모두 111개 대상 중 0건이다.

## 2. 전체 응답은 OpenClaw가 더 빨랐다

**같은 질문·단계의 113개 응답쌍을 비교했다.** 측정이 모호한 한 사례는 양쪽 비교에서 제외했다. P90은 응답 90%가 해당 시간 이내에 끝났다는 뜻이다.

| 지표 | OpenClaw | Hermes |
| :--- | ---: | ---: |
| 중앙 응답 시간 | **18.48초** | 22.20초 |
| 평균 응답 시간 | **27.26초** | 33.77초 |
| P90 응답 시간 | **54.51초** | 70.56초 |
| 입력 토큰 합계 | **10,942,536** | 11,876,060 |
| 출력 토큰 합계 | **75,247** | 82,821 |

기억 회수와 검색만 보면 Hermes의 중앙 시간은 더 짧았다. 기억 회수는 **13.07초 대 27.74초**, 검색은 **35.08초 대 45.89초**였다. 다만 검색 P90은 Hermes **177.40초**, OpenClaw **105.87초**로 Hermes에 오래 걸리는 사례가 있었다.

> [!info] 토큰 사용량과 요금은 다르다
> 입력 토큰에는 캐시 읽기·쓰기 토큰이 포함된다. 입력 토큰 7.9% 감소를 실제 요금 7.9% 절감으로 해석할 수 없다. 시간은 에이전트의 native trace 기준이며 외부 실행·추출 대기 시간과 분리했다.

## 3. Trajectory & Tool Use · 제약 준수와 복구 과정

**도구 호출 수는 Hermes가 적었고, 도구 금지 준수는 OpenClaw가 좋았다.** 호출 수에는 도구 설명과 래퍼 호출이 포함돼 단순히 적을수록 좋다고 볼 수 없다.

| 관측 항목 | OpenClaw | Hermes |
| :--- | ---: | ---: |
| 도구 호출 · 학습 포함 126회 실행 | 963회 | 507회 |
| 도구 금지 문항 준수 | **3 / 3** | 2 / 3 |
| 실행 종료·비어 있지 않은 답변 | 126 / 126 | 126 / 126 |

Hermes는 E2에서 도구 사용 금지를 위반했다. OpenClaw는 검색 도구의 공급자 비활성화 오류 16회 이후 다른 자료 확보 경로로 검색 답변을 완성했다. 이는 복구 성공의 관측이며, 오류가 없었다는 뜻은 아니다.

> [!note]- 오류율을 직접 비교하지 않은 이유
> OpenClaw는 native 오류 플래그 41건을 관측했다. Hermes는 반환 본문에서 오류 46건을 확인했지만 native 오류 플래그는 관측 불가였고 반환 상태 6건도 불명확했다. 집계 기준과 관측 범위가 달라 오류율 순위를 매기거나 두 오류 기준을 합산하지 않았다.

## 4. Component-level · 기억 회수와 저장 판단은 다른 성능이다

**Hermes는 필요한 사실을 회수·수정하는 데 강했고, OpenClaw는 불필요한 내용을 저장하지 않는 데 강했다.**

| 기억 구성요소 | OpenClaw | Hermes |
| :--- | :--- | :--- |
| 사실·수정 기억 회수 | 3 / 4 | **4 / 4** |
| 선호 적용 | **2 / 2** | 1.5 / 2 |
| 수정 기억의 일관성 · 해당 사례 | 최신 값과 옛 값이 서로 다른 저장소에 공존 | **옛 값 제거** |
| 잡음의 장기 저장 방지 | **2 / 2 통과** | 0 / 2 · 두 건 저장 |
| 더미 비밀값의 장기 저장 방지 | **2 / 2 통과** | 0 / 2 · 두 건 저장 |

Hermes는 잡담과 일회성 계산, 시험용 키·비밀번호를 장기 기억에 남겼다. OpenClaw는 해당 네 사례의 저장을 피했다. 따라서 기억 회수 정확도가 높다는 사실만으로 저장 필터링까지 좋다고 판단할 수 없다.

> [!important] 저장 감사의 범위
> 읽을 수 있는 장기 기억과 기억 전용 색인을 실행 전후 비교하고, 60초 지연 스냅샷으로 재확인했다. 원시 대화 로그는 제외했다. 노출되지 않은 자동 추출의 최종 상태는 미확인이다. 각 저장 방지 결과는 시험한 2건에 한정하며, 실제 비밀값 유출이나 보편적인 보안 수준을 뜻하지 않는다.

검색 구성요소에서는 양쪽 모두 H 8문항을 충족했다. 별도 공개 출처 표본 감사에서 17개 인용·16개 고유 출처의 접근과 본문을 검증했다. 모든 검색 답변의 모든 출처를 전수 검사한 결과는 아니다.

## 5. 다음 개선은 점수보다 약점에 맞춘다

1. **Hermes · 저장 필터링 개선:** 일회성 대화와 민감한 값의 저장 억제, 도구 사용 금지 준수를 우선 검증한다.
2. **OpenClaw · 기억 일관성 개선:** 저장소 사이의 옛 값 잔존과 사실 회수 실패를 우선 검증한다.
3. **양쪽 · 반복 평가:** 경계 문항 기준을 정리한 뒤 여러 번 실행해 순위와 응답 시간 변동을 확인한다.

추가로 확인할 질문은 **“어떤 설정 차이가 기억 회수·저장 필터링의 차이를 만드는가?”**, **“적은 도구 호출이 실제로 더 적절한 도구 선택을 뜻하는가?”**다. 현재 결과만으로 두 질문의 원인을 확정할 수 없다.

## 평가 범위와 근거

> [!example]- 실행·채점 방법
> **데이터셋:** A–H 총 130문항. 저장 감사 4문항은 답변 정확도와 분리했다.
> **주 실행:** 두 에이전트 합계 252회. 학습 단계와 묶음 답변을 포함하므로 문항 수와 호출 수는 다르다.
> **기억 초기화:** 평가 범위의 기억·색인·이력을 초기화한 뒤 기억 평가를 다시 실행했다. 초기화가 불완전했던 최초 기억 실행 36회는 대조군으로 보존하고 주 비교에서 제외했다.
> **공동 검토:** Claude는 블라인드 답변 채점, Codex는 실행·계측·기준 조정 감사, Antigravity는 출처와 저장 의미 검토를 맡았다. 세 검토자를 독립적인 동일 답변 투표로 취급하지 않았다.
> **기록:** 데이터셋·실행 결과·검토 근거를 MLflow에 저장하고 재조회했다. LangChain autolog를 사용하며 에이전트 파라미터로 결과를 구분했다.

> [!warning]- 완료한 평가와 아직 측정하지 않은 항목
> 완료 범위는 답변 품질·효율, 도구 호출·제약 준수·복구 관측, 검색·기억 회수·갱신·필터링 감사다.
> **계획의 적절성, 도구 선택·인자 정확성, 불필요한 호출 비율, 단계별 목표 달성률의 독립 정량 점수는 산출하지 않았다.** 정답만으로 장기 기억의 독점적인 기여를 입증하지 않는다.
> 현재 구성의 1회 결과이며 제공 경로·도구 구성의 차이가 있다. 신뢰구간이나 보편적인 인과 순위는 제시하지 않는다.

근거는 최종 결과 집계, native 실행 계측, 도구 과정 감사, 기억 저장 전후 비교, 블라인드 채점과 민감도 분석에 기반한다. 재현용 상세 자료는 별도로 보존하며 이 공개 문서에는 운영 식별자와 접속 정보를 싣지 않는다.

공개본은 실제 서비스 주소·계정·접속 정보와 내부 운영 경로를 제외했다.
