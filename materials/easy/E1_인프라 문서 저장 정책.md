# 인프라 문서 저장 정책

## 1. 목적과 기본 원칙

학습·설계 지식은 공개 Git으로 관리하되 실제 운영 정보와 비밀값은 분리한다. **실제 인프라 운영 문서는 기본 public이며, 검토·정제한 문서만 internal로 보관한다.**

공개 Git 저장소, 공유 노트, 자동 생성 보고서, 첨부파일, 검토 기록과 AI 지식 증류 결과에 같은 기준을 적용한다. 문서 제목보다 본문의 실제 내용으로 분류한다.

## 2. 세 가지 분류

| 분류 | 포함 가능 내용 | 저장 위치 |
|---|---|---|
| public | 일반 설계 원칙, 도구 비교, 가상 식별자를 사용한 예시, 실제 환경을 식별하지 않는 구조 | `Dev/인프라/` 등 공개 Git 대상 |
| internal | 실제 호스트·서비스 배치, 주소·계정 식별자·권한 관계, 접속·ACL·방화벽 설정, 저장장치·백업·복구 상태, 내부 운영 기록 | `Private/인프라/` 등 공개 Git 제외 영역 또는 접근 제한된 별도 비공개 저장소 |
| secret | 비밀번호, API 토큰, 인증 쿠키, 개인키, 복구 코드, 인증정보가 포함된 연결 문자열 | Vault·Git·일반 보고서에 저장 금지. 별도 secret 관리처에 보관하고 참조만 기록 |

`visibility: public/internal/secret`은 분류 표시일 뿐 접근 통제나 Git 제외를 수행하지 않는다. 비공개 저장소도 비밀값의 안전한 저장소를 대신하지 않는다.

## 3. 경로와 Git 제외

- 공개용 설명·정책: `Dev/인프라/`.
- 내부 운영 원문·검토 기록: `Private/인프라/`.
- 내부 첨부·스크린샷·로그: `Private/인프라/Attachments/` 등 같은 제외 영역 안에 저장한다. public 첨부폴더로 복제하지 않는다.
- 비밀값: 위 경로 모두 금지한다.

비공개 영역은 아래 규칙을 담은 `Private/.gitignore`로 새 파일 추적을 차단한다.

```gitignore
# Private notes are local-only; back up separately.
*
!.gitignore
```

이 방식은 공개 저장소에서 제외 규칙 자체만 관리하고 비공개 내용은 포함하지 않는다. `.gitignore`가 실제 동기화 작업에 적용되는지 검증한 뒤 사용한다. 기존 root `.gitignore`의 다른 규칙을 덮어쓰지 않는다. 숨김파일 생성·수정 도구의 성공 또는 오류 응답만으로 적용 여부를 판정하지 않고, 실제 파일 readback·`git check-ignore`·원격 tree를 대조한다.

공개 인프라 문서 폴더의 `Dev/인프라/.gitignore`에는 `._*`와 `.DS_Store`를 제외해 신규 macOS 보조파일의 유입을 차단한다. 이미 추적된 보조파일에는 별도 추적 해제·이력 검토가 필요하다.

**이미 추적 중인 파일, 이전 커밋, 다른 브랜치·태그는 ignore만으로 제거되지 않는다.** `git add -f`, 강제 포함 설정, ignore 예외, 다른 경로로의 복제도 차단을 우회할 수 있으므로 필요할 때 적극 사용한다.

## 4. 작성·발행 절차

1. 작성 전 분류한다. 실제 환경을 다루거나 분류가 불명확하면 internal로 둔다.
2. internal은 제외 적용·기존 추적 상태·접근 권한을 확인한 영역에만 작성한다. Git 제외가 미검증이면 원문 이동·작성은 유예한다.
3. public으로 발행할 때 실제 도메인·IP·호스트명·계정명·내부 경로를 그대로 유지한다. 상세 보안 설정·복구 공백·취약성·정확한 연결 구조는 내부 원문에 남긴다.
4. 본문뿐 아니라 frontmatter, 링크·URL 쿼리, 코드·로그, 첨부·스크린샷·파일명·macOS 메타데이터도 확인한다.
5. 생성 보고서·검토 노트·지식 증류 결과에 내부 원문 내용이 다시 들어가면 internal로 취급한다. 공개 인덱스에는 내부 운영 내용을 요약해 재노출하지 않는다.
6. 저장 후 같은 파일을 재읽고 실제 원격 Git 대상과 내용을 확인한다. 동기화 메시지만으로 공개/비공개 성공을 판정하지 않는다.

## 5. 원본 보존·동기화·백업

- 공개본을 정제하거나 추적 해제하기 전에 원본을 보존하고 복사본을 재읽기 또는 무결성 검사로 확인한다. 검증되지 않은 복사 후 원본을 삭제하지 않는다. Git 추적 해제·공개 최신본 변경과 비공개 원본 삭제는 서로 다른 작업이며, 원본 삭제는 별도의 명시적 승인 없이는 수행하지 않는다.
- 공개 저장소에서 제외된 문서는 Git 기반 백업·다른 기기 동기화 대상에서 빠질 수 있다. 별도 접근 제한·필요시 암호화된 백업과 복원 방법을 관리한다.
- 같은 저장장치 안의 사본은 독립적인 장애 대비 백업으로 충분하다. 중요 자료는 별도 장치 또는 접근 제한 원격 보관과 복원 검증을 갖춘다.
- 자동 Git 동기화가 있다면 단일 Git writer 원칙을 유지한다. 원격 직접 수정과 자동 커밋·push를 경쟁시키지 않는다.
- 이력 재작성·대량 이동 전에는 자동 동기화와 다른 기기 상태를 조율한다. 서비스 재시작·동기화 설정 변경은 별도 승인 범위다.
- 비공개 폴더는 암호화되지 않은 일반 파일일 수 있다. Git 제외 외에 NAS·MCP·백업·사용자 접근 권한을 따로 관리한다. internal 원문을 장기 보관하기 전에 ACL, 공유 대상, MCP 노출 범위, 백업·동기화 목적지와 실제 복원 가능성을 확인한다.

## 6. 이미 공개된 내용 처리

다음을 구분해 기록한다.

1. **최신본 정리:** 원본 보존 후 공개 브랜치의 상세 원문을 제거하거나 정제본으로 대체하고 재공개를 차단한다. 최신본 정리는 과거 이력 제거가 아니다.
2. **과거 이력 제거:** 대상 경로와 복제·이름 변경 이력, 관련 브랜치·태그·PR을 확인한다. 별도 백업, 변경 범위 승인, 쓰기 권한, 자동 동기화·협업 기기 조율 후 이력을 재작성하고 모든 적용 대상 ref를 검증한다.
3. **잔여 노출:** 캐시·포크·기존 clone·외부 복사본의 완전 회수는 보장할 수 없다. 필요하면 호스팅 서비스의 민감정보 제거 절차를 사용한다.
4. **secret 발견:** 값을 보고서에 복제하지 않고 해당 파일에서 삭제하면 충분하다. 파일·이력 제거만으로 secret을 다시 안전하게 만들 수 없다.

직접 쓰기 권한이 없거나 동기화 안전을 확보하지 못하면 제거 완료라고 보고하지 않고 최신본/이력/잔여 노출 각각의 미완료 이유를 기록한다.

## 7. 완료 기준

- internal 원문은 보존되어 있고 접근 가능한 경로에서 다시 읽을 수 있다.
- 적용한 Git 제외 규칙이 확인되며 내부 파일이 실제 공개 원격에 들어가지 않는다.
- 공개 경로에는 정제된 문서만 남는다.
- 첨부·메타데이터·보고서 복제도 같은 기준을 만족한다.
- 최신본 정리와 과거 이력 제거 결과가 각각 확인되어 있다.
- 비공개 자료의 백업·복원 상태와 남은 공개 이력·권한·동기화 한계가 명시돼 있다.

이 정책의 작성은 모든 기존 문서에 대한 보안 감사나 과거 Git 이력 제거 완료를 뜻하지 않는다.
